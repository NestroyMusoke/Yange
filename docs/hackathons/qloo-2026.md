# Yange for the Qloo Agentic Hackathon

## Pitch

Yange helps you choose a day out that reflects your tastes, then dress for it using clothes you already own. Qloo connects your favourite artists, films, brands and places to places in your city. Yange turns the chosen place into outfit-planning context, checks real garment availability, and lets you reserve a feasible outfit.

## Existing work and new work

Baseline: `bc3ae0512248aa4f91bc94d6797c43f560050b70`, the existing Yange project by Musoke Nestroy. The team is extending this project together. Preserve the MIT license and original attribution.

Existing: wardrobe capture, care evidence, outfit scoring and reservations, confidence feedback, WearCast laundry planning, virtual preview and cloud infrastructure.

New for this submission: Qloo entity search, user-confirmed interests, taste-grounded place recommendations, a receipt naming the chosen interests, and transfer of a selected Qloo place into outfit planning. The separate wardrobe-search improvement is usability work, not the Qloo differentiator.

Do not present the baseline as newly built for this hackathon. Record the final commit and describe the integration as an extension.

## Architecture and boundaries

1. The user searches and selects 1–5 actual Qloo entities. Search is explicit, not sent on every keystroke.
2. The server calls `GET /search` with `query`, `types`, and `take`.
3. The server calls `GET /v2/insights` with `filter.type=urn:entity:place`, `signal.interests.entities`, `filter.location.query`, `filter.location.radius=0`, `filter.tags` for restaurant/night-club genres, `operator.filter.tags=union`, and `take=6`.
4. Results retain Qloo's order. The UI names the input interests; it does not claim a per-interest explanation or invent affinity percentages.
5. Selecting a place fills the occasion title. The user confirms date, occasion, dress code and weather before generating outfits. Qloo does not establish venue dress requirements or determine garment suitability.
6. The existing deterministic planner excludes unavailable garments. Reserving a candidate continues through the existing event ledger. Calendar notes retain the Qloo place ID, retrieval time and bounded interest names.

The API key is server-only. Requests always use `https://hackathon.api.qloo.com` and `X-Api-Key`, with a ten-second timeout and redirects disabled. Search strings, interest IDs and city are sent to Qloo; wardrobe photos, measurements and session IDs are not. Responses contain only selected fields. There is a process-wide limit of 30 taste requests per minute; for multi-instance deployment use provider quotas and a shared gateway limit as appropriate.

Missing keys, unavailable providers, invalid payloads and empty results are explicit states. There are no sample recommendations disguised as live Qloo output. Live requests on 2026-10-19 returned Kampala venues for Beyoncé and Miles Davis. Coverage for other interests and locations still needs validation. Profile city remains the context for both discovery and outfit weather. This release does not book venues, verify opening hours, or automatically infer a dress code.

## Local setup

Requires Node 22 or later. From the repository root:

```sh
npm ci
cp .env.example .env
```

Add the hackathon key to `QLOO_API_KEY` in `.env`. Keep it out of source control and do not use a `VITE_` prefix. Request a key from the official guide linked below if needed.

Start the API in one terminal:

```sh
node --env-file=.env --import tsx apps/api/src/server.ts
```

Start the frontend in another:

```sh
npm run dev
```

Open `http://127.0.0.1:4173/?view=atelier`. Complete onboarding or explore with sample clothes, then open Outfits. The development client uses `http://127.0.0.1:8080` by default.

For the production deployment, inject `QLOO_API_KEY` as a server secret on the public edge service using the existing secret-management process. Rebuild and deploy the application using the project's cloud deployment instructions. Do not embed the credential in build arguments, client environment variables, documentation or screenshots. Do not replace the configured Google runtime with local in-memory mode for the public submission.

## Validation and judge journey

Automated checks:

```sh
npm test
npm run typecheck
npm run build
```

Implementation verification on 2026-10-18: 124 automated tests passed; workspace type checks and production build passed. An isolated browser preview with explicitly labelled fixture data completed interest search, selection, place discovery, outing handoff, outfit generation and reservation. That preview was not live Qloo verification. On 2026-10-19, the real hackathon API and Yange’s local API both successfully completed search and Kampala recommendations. Different artist signals returned different ordered results. An unrestricted place query included irrelevant businesses, so discovery now requests restaurant/night-club genre tags. Provider classifications and current venue details should still be checked by the user.

Live acceptance (requires a real key and public deployment):

- Search for an artist or film and confirm a correct Qloo entity; use a second interest from another category.
- Discover places in the profile city. Check that returned places are actually in the intended locality. If none are available, show the honest empty state; do not silently substitute another city.
- Choose a place, set a future date and confirm occasion/dress code. Generate and reserve an available outfit.
- Inspect the planned outfit receipt and stored Qloo place reference.
- Repeat with contrasting interests and record how recommendations change. Do not promise different results for every pair or claim measured quality gains without evaluation.
- Exercise unavailable Qloo, empty results and retry. Verify key values never appear in browser responses or bundles.
- Test the public demo in a signed-out browser and on a phone.

## Suggested submission description

Yange connects what you love to where you go—and what you already own. Choose favourite artists, films, brands or places, and its Qloo integration finds culturally relevant places in your city. Select an outing and Yange builds feasible outfit options from your wardrobe, considering your occasion, weather and garment availability. You remain in control of the dress code and reservation.

Qloo provides the cultural discovery; Yange provides wardrobe planning and preparation. Without Qloo, the existing app can dress you for a manually entered occasion, but it cannot offer this taste-grounded discovery journey. Our hackathon work adds that capability to the existing open-source Yange agent. We surface the selected interests and preserve the Qloo place reference without claiming taste correlations prove why an individual will like a venue.
