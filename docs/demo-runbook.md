# Yange four-minute demo runbook

This is a live, unedited causal story. Rehearse it locally, then record the identical journey on the deployed Cloud Run URL. Use `/?mode=judge` as the opening and closing director; never imply that a local receipt is Google evidence.

## Before recording

1. Run `npm.cmd install` and `npm.cmd run dev:cloud`, or deploy with `scripts/deploy-google-cloud.ps1`.
2. Run `scripts/verify-phase6.ps1`.
3. Prepare two non-sensitive images: one garment with a readable care label and one outfit-inspiration image or saved social-video frame.
4. Set the browser near 1440 × 900, close unrelated tabs, silence notifications, and enable Do Not Disturb.
5. Open `/?mode=judge`, click **Reset deterministic demo**, and confirm all six proof lights are honest waiting states.
6. For the deployed take, open **Cloud proof** once and confirm **Google Cloud live** before recording.

## The live take

### 0:00–0:50 — Teach, do not assume

Say: “Yange starts with evidence, not a shopping catalogue.”

- Open **Wardrobe Studio**.
- Add the garment image and optional care-label image.
- Point out on-device signature checking, metadata-stripping rewrite, private image storage, provenance badges, and the mandatory review state.
- Save the garment.
- Add the inspiration image or saved social-video frame, show the structured Look DNA palette/silhouette result, and confirm it.

Proof: multimodal intake, privacy boundary, versioned model output, human confirmation.

### 0:50–1:35 — Plan from reality

Say: “The model cannot invent clothes or override availability.”

- Open **Decision Atelier**.
- Request Friday dinner using the available context.
- Show the ranked feasible candidates and the five-factor Personal Match receipt.
- Point to weather, calendar, care practicality, Style Memory, and deterministic tie-breaking.
- Reserve the best candidate and show garment dependency reservations.

Proof: constrained planning, explainability, live state, model containment.

### 1:35–2:20 — Learn from a lived experience

Say: “Personalisation comes from how Amina felt, not a body judgement.”

- Open **Today** and mark City Calm worn.
- Show the cotton blouse moving to laundry, trousers becoming rewearable, jacket airing, and shoes/accessories staying available.
- Record a Confidence Check-in.
- Open **Style Aura** briefly: show chosen colours, inspiration swatches, confidence signals, and the slowly evolving palette.

Proof: material-aware state, event memory, user-controlled feedback, visible learning.

### 2:20–3:25 — Let the agent act

Say: “Now a future outfit depends on garments that are leaving rotation.”

- Open **WearCast** and stage the labelled 50% wardrobe-pressure fixture.
- Compare the untouched **Do nothing** branch with **Autopilot**.
- Show the Kampala drying-suitability horizon, laundry groups, Friday dependency risk, and verified fallback.
- Run once with the notification outage switch. Show the failed delivery checkpoint after the valid intervention commit.
- Resume. Show checkpoint skipping, one delivered notification, a reserved fallback, and no duplicate event.

Proof: asynchronous autonomy, forward simulation, weather-aware action, retry and idempotency.

### 3:25–4:00 — Break beauty, prove production

Say: “Even the signature visual is expendable; the wardrobe agent is not.”

- Return to **Judge mode**, simulate renderer loss, and point out unchanged readiness/state; restore it.
- Open **Cloud proof**.
- Show Google runtime mode, the public edge/private worker boundary, six server checkpoints, trace ID, revision, and service evidence.
- Finish on the architecture diagram and the line: “AI proposes. Validated rules commit. Yange acts before the problem becomes your problem.”

Proof: graceful degradation, observability, reproducible Google Cloud execution.

## If something fails live

- Image model unavailable: show the retained rewritten image and explicit retry; do not save unreviewed facts.
- Notification delivery unavailable: this is the planned failure proof; resume the same run.
- WebGL unavailable: keep the still fallback and continue; this proves the boundary.
- Cloud runtime not in Google mode: stop calling it deployed proof. Continue with the local rehearsal and record the Google take after configuration is fixed.
- Weather unavailable in cloud: use the stored validated snapshot only if the UI labels its source and age.
